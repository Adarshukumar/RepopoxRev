# 06 — Providers

Providers are the self-contained "content backends" — plain Kotlin Android libraries that
talk to an external service and expose a stable object. The app calls them; they never
touch the UI.

## 1. InnerTube (`providers/innertube/`, ~8.3k LOC, 105 files) — YouTube Music

The biggest and most important provider. It is a **reverse-engineered YouTube Music
client** that speaks the private **InnerTube** API directly (no YouTube Data API, no OAuth
for browsing — only the session cookie from in-app sign-in).

### Structure
```
com.music.innertube/
├── InnerTube.kt         HTTP client (Ktor+OkHttp), proxy, DNS, compression
├── YouTube.kt           the API facade (~1700 LOC, ~120 methods)
├── Captions.kt          caption parsing
├── NetworkConfig.kt     network config
├── OfflineModeException.kt
├── YouTubeConstants.kt  client names, API keys, context templates
├── models/              request/response models (protobuf-ish, serialized JSON)
│   ├── body/            PlayerBody, NextBody, SearchBody, BrowseBody, …
│   ├── response/        NextResponse, PlayerResponse, SearchResult, …
│   ├── context/         Context, Client, Endpoint
│   └── …                SongItem, AlbumItem, ArtistItem, Renderer types
├── pages/               HomePage, SearchPage, AlbumPage, … (parsed browse responses)
└── utils/               parseCookieString, sha1, …
```

### `InnerTube` (the HTTP layer)
- Ktor `HttpClient(OkHttp)` with `expectSuccess`, JSON content negotiation
  (`ignoreUnknownKeys`, `explicitNulls=false`, `encodeDefaults=true`), gzip/deflate.
- Configurable: `locale` (gl/hl), `visitorData`, `dataSyncId`, `cookie`, `proxy`,
  `proxyAuth`, `ipVersion` (AUTO/IPv4/IPv6/DoH), `useLoginForBrowse`, `offline`.
- Changing proxy/ipVersion **rebuilds** the client (closes old, creates new).
- DNS-over-HTTPS support (`okhttp-dnsoverhttps`).

### Clients & context
`YouTubeConstants.kt` defines InnerTube client contexts (ANDROID, IOS, WEB, MWEB,
TVHTML5, VISIONOS, …) with their `clientName`, `clientVersion`, `userAgent`, and API keys.
`Context` builds the request context (client + auth + visitor). Different clients yield
different streaming qualities and behaviours.

### The PoToken / BotGuard dance
YouTube now requires a **Proof-of-Origin (PoToken)** for streaming. Mochy solves this
**on-device**:
- `app/src/main/assets/po_token.html` — a BotGuard client (runs in a WebView).
- `app/src/main/assets/solver/` — `meriyah.js` (JS parser), `astring.js` (code generator),
  `yt.solver.core.js` (the solver, auto-generated by yt-dlp's `ejs`).
- `utils/potoken/` + `YTPlayerUtils.preWarmPoToken()` — boots the WebView, runs the
  challenge, mints the token. `App.onCreate` pre-warms it after the intro (see `03`).
- Without a token YouTube serves only a ~32s preview — so this is essential.

### Widevine / DASH
`custom/WidevineDrm.kt` handles Widevine CDM licensing for DASH streams (the device's own
CDM decrypts, like the web player). `DynamicResolvingMediaSource` refreshes licenses.

## 3. `lastfm` (`providers/lastfm/`)
Last.fm + Libre.fm API: track info, love/scrobble, auth. Keys from `local.properties`/CI
secrets (never committed); Libre.fm gets a deterministic MD5 stand-in when no key is set.

## 4. `canvas` / `applecanvas` / `artistvideo` — animated artwork
Apple-Music-style animated canvases and artist background videos. `AppleMusicToken.kt`
handles the Apple Music token (used to fetch canvases). `MonochromeAlbumCanvas` /
`MonochromeApiCanvas` for the Monochrome module.

## 5. `shazamkit` — music recognition
Shazam signature generation (`ShazamSignatureGenerator`, `VibraSignature`) + the
recognition service (`recognition/MusicRecognitionService.kt`). Microphone-based, optional.

## 6. `kugou` — KuGou music search/lyrics
Chinese music service; `KuGou.useTraditionalChinese` for zh-TW.

## 7. `wikipedia` — artist info
Artist Wikipedia summaries/bios.

## 8. How the app picks a provider

`SourceModules` walks a **provider order** (modules first, then YouTube, then any others)
calling `resolve(track)` until one returns a stream. `LyricsProviderRegistry` does the
same for lyrics (see `10-lyrics.md`). The order is user-configurable and persisted.
